取引先の登録番号(適格請求書発行事業者の T から始まる番号)が、取消・失効していないかを確かめる道具「取引先インボイス見張り」を作りました。前の記事では Python の本体と国税庁の公表データの決まりを書きました。この記事は別の切り口で、**取引先の一覧という見せたくない表を、どこにも送らずにブラウザだけで照らす**ための作りを書きます。税務の助言ではありません。

https://github.com/japan-ai-tools/invoice-watch

## なぜ「送らない」にしたか
取引先の一覧には、会社名と、個人事業主なら氏名が入ります。国税庁の公表データの運営方針も、個人の氏名を本人の同意なく公表しないこと、登録番号の有効性の確認という目的の範囲で使うことを求めています。

そこで画面(`web/`)は、読み込んだ CSV を端末の中だけで照らし、結果も端末の中で CSV に書き出す作りにしました。サーバーに表を預かる仕組みを持たないので、預かったデータが漏れる心配の元がそもそもありません。

## 通信を止めるのは「書かない」ではなく CSP で
「fetch を書いていないから通信しない」は、あとで誰かが1行足せば崩れます。そこで HTML の Content-Security-Policy で、ページが外へつなぐこと自体を止めています。

```html
<meta http-equiv="Content-Security-Policy"
  content="default-src 'none'; script-src 'self'; style-src 'unsafe-inline';
           img-src 'self' data:; connect-src 'none'; form-action 'none'; base-uri 'none'">
```

- `connect-src 'none'`: fetch・XMLHttpRequest・WebSocket を止める
- `form-action 'none'`: フォームの送信先を作らせない
- `script-src 'self'`: 置いた自分のファイル以外の JavaScript を読まない(外部の解析タグなども入らない)

ブラウザ(スマホの幅 375px)で開いて、読み込みから書き出しまでの間に外への通信が1件も出ないことと、コンソールにエラーが無いことを確かめました。

## Python と JavaScript で答えを1つにする
照合の決まりは Python の本体(`invoicewatch/watch.py`)と、画面用の `web/watch.js` の2つに書いています。2つが別の答えを出すと、どちらを信じればよいか分からなくなります。

そこでテスト(`tests/test_web.py`)で、同じ見本の取引先 CSV と公表データを両方に入れ、node で動かした JavaScript の結果と Python の結果が同じになることを確かめています。見るのは次の点です。

- 状態(登録中・取消・失効・登録日より前・見つからない・形の誤り)
- 取引日の時点での判定(取消・失効の後も公表データに7年載るので「載っている=登録中」ではない)
- 名称の食い違い(「(株)」と「株式会社」は同じとみなす)
- 前回の結果と比べた「変わった取引先だけ」の差分
- CSV の読み込み(`"見本, ""株"""` のような引用符とカンマを含む名前)

いまのテストは本体と画面を合わせて28件で、すべて合格しています(自分で作った見本での結果です)。

## 使い方
1. `web/index.html` を開く
2. 取引先の一覧(名前・登録番号の CSV)を入れる
3. 国税庁の公表データ(ダウンロードの JSON か、見出しつきの CSV)を入れる
4. 取引日を選んで確かめる。結果は CSV で書き出せる。前回の結果を入れると、変わった取引先だけが出る

無料の版は先頭の10件までです。

## できないこと
- 公表データを自分で取りに行きません。国税庁のダウンロードのページから人が取って入れます(公表サイトの検索画面をプログラムで取ることはサイト利用規約で禁止されています)
- 個人事業者は、ダウンロードデータでは氏名が空です。名称の食い違いは確かめられないので「目で確かめる」と出します
- 見出しの無いダウンロードの CSV は、列の並びを実物で確かめるまで受け付けません。JSON を使ってください
- 国税庁の公式の道具ではなく、結果は国税庁が保証したものではありません。大事な取引は国税庁の公表サイトでも確かめてください
