AIエージェントに請求書を作らせると、消費税を品目ごとに端数処理して足してしまうことがあります。インボイス制度では、端数処理は「1つの請求書につき、税率ごとに1回」です([国税庁のパンフレット](https://www.nta.go.jp/publication/pamph/shohi/shohizei_11.pdf))。

| 品目(税抜・10%) | 金額 | 品目ごとに切捨て |
|---|---|---|
| コピー用紙 | 1,999 | 199 |
| トナー | 2,999 | 299 |
| ボールペン | 999 | 99 |
| 合計 | 5,997 | 597(正しくは 599) |

この1〜2円のずれを止めるために、適格請求書を検査する道具 JP Invoice Check を作って公開しています。この記事では、作り方ではなく「どこに置いて、どう使うか」を書きます。Qiita で読者の方からもらった指摘を取り入れた 0.2.0 の話です。

## 指摘1: 検査をAIが書き換えられる場所に置くと、意味が薄れる

工場の検査の基準を、現場が勝手に変えられないようにするのと同じです。AIが検査の道具そのものや、端数処理の指定を書き換えられたら、検査は形だけになります。

そこで 0.2.0 では次のようにしました。

- 会社の規則(端数処理の方式と、税抜か税込か)は、人が道具を起動するときにだけ読み込む。AIからの呼び出しでは変えられない
- 請求書の中に「四捨五入でいい」と書いてあっても、規則が優先される(無視したことを知らせる)
- 結果に、検査に使ったコードの指紋(sha256)を付ける。書き換えられたら値が変わる

置き方の例です。道具はAIが作業するフォルダの外に入れ、MCPサーバーとして別の動きで動かします。

```bash
pip install "git+https://github.com/ayatrader/jp-invoice-check"
```

```json
{"mcpServers": {"jp-invoice-check": {"command": "jp-invoice-check",
  "args": ["--policy", "/etc/company/invoice_policy.json"]}}}
```

規則のファイルは読み取り専用にして、AIのフォルダの外に置きます。Claude Code なら、その場所への Edit と Write を許可しない設定にします。

## 指摘2: 端数処理の方式は、自社で1つに決めて文書にしておく

```json
{"name": "自社の請求書の規則", "rounding": "floor", "price_basis": "exclusive"}
```

この1行を決めておくと、検査結果との見比べが1回で済みます。

- 自社が出す請求書(`role: issue`): 規則と違えば誤り
- 取引先から来た請求書(`role: receive`): 方式が違うこと自体は問題ないので警告。「相手は四捨五入で計算しているので、自社の規則より +1円」のように、ずれの理由と金額を返す

取引先と金額が合わないとき、原因を探すやりとりが減ります。
